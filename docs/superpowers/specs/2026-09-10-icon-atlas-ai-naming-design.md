# 图集 AI 识别与自动重命名设计

## 目标

在图集拆分前，用一次 Codex CLI 调用识别图标顺序和图标下方名称，并生成可供抠图使用的无文字图集（若生成失败则回退到原图）。拆分结果继续使用稳定的行优先编号；只有识别结果完整且通过安全校验时才自动重命名。

## 数据流

```text
原图
  ├─ 本地生成识别副本（大图自适应缩小、JPEG 压缩）
  ├─ Codex CLI：返回 JSON 名称映射 + 可选无文字图集
  └─ 本地：使用无文字图集/原图抠图 → 行优先拆分 → 编号 → 安全重命名
```

## 识别输入与额度控制

- 每张原图最多调用一次 AI。
- 最长边不超过 2048px 的图片直接使用；超过时缩放到最长边 2048px。
- 保持文字可读性，缩放后不再继续压缩过小的文字区域；识别副本使用 JPEG 质量 88。
- AI 只接收识别副本，不接收拆分后的每个散图。
- 使用原图文件哈希、尺寸和识别参数组成缓存键；缓存命中时跳过 CLI 调用。
- 提示词要求只输出机器可解析 JSON，关闭不必要的工具调用，并限制输出长度。

## AI 输出协议

```json
{
  "items": [
    {"index": 1, "name": "训练木剑"},
    {"index": 2, "name": "克劳德的水壶"}
  ],
  "has_readable_names": true,
  "clean_image_path": "..."
}
```

`index` 是从左到右、从上到下的视觉顺序，不依赖 AI 自己的坐标编号。名称无法确认时必须返回空字符串。无文字图集作为可选输出：若 Codex CLI 无法生成或返回文件不存在，流程记录警告并回退到原图。

## 本地拆分与重命名

- 继续调用现有 `segment_icons`，使用行优先排序。
- 先保存临时编号文件，再执行重命名，避免中途失败造成部分覆盖。
- 名称经过文件名安全化：去除 `\\ / : * ? " < > |`、控制字符和首尾空格，限制长度，并处理重复名称。
- 只有 AI 返回的数量与拆出图标数量一致、所有名称非空且名称通过安全化后仍有效时，才批量使用 AI 名称。
- 任一条件不满足时，保留 `原图名_1.png` 等编号文件，并在日志中说明原因。
- 同名名称增加稳定后缀，例如 `名称_2.png`。

## 失败处理

- 找不到 `codex` CLI、CLI 未登录、超时、JSON 无法解析或图像输出失败：不阻断普通拆图，使用原图和编号命名继续完成。
- AI 识别失败不得删除或覆盖已有输出。
- 缓存只保存成功解析的 JSON；失败结果不写入成功缓存。

## UI 与打包

- 在图集拆分页增加“AI 识别并重命名”开关，默认关闭，避免改变现有用户行为。
- 增加 AI 处理日志和缓存命中日志。
- 后端负责临时文件、CLI 子进程、JSON 校验和重命名；前端只传开关并显示进度。
- 打包时不内置 Codex CLI，运行时检查系统 PATH；缺失时提示并回退普通拆图。
- 新增后端自测覆盖：缩放规则、缓存键、JSON 校验、文件名安全化、重复名、失败回退和行优先映射。

## 取舍

本阶段优先保证额度、可回退性和不误命名。AI 去文字图集生成属于可选能力，不让它成为拆图成功的前置条件；后续可在真实 CLI 输出验证后再强化提示词或增加人工确认预览。
